# XBoard Friend Invite 0.1.1

基于 0.1.0 的修复版本，保持邀请生成、套餐赋予和五种使用期限规则，不修改 XBoard 源码，无新增数据库表。

## 修复

- 容器重建后恢复缺失的公开控制台资源，复制失败保留重试状态；新增部署自检和资源修复 CLI。
- HTTP 500 返回脱敏诊断编号与错误位置；数据库不可用时保留独立文件日志。检查已加载组件接口，帮助排查未重启的 PHP 进程。
- 配置保存增加版本冲突检查，Debug 修改统一加锁；过期页面无法静默覆盖新设置。
- 刷新机器人状态、解绑和断开不再覆盖设置草稿。关闭控制台提供保存、放弃、继续编辑，并清除其他标签页中的敏感状态。
- TG 连接、断开先保存待恢复状态，失败后可继续使用相同操作与密钥恢复。远端 Webhook 已被其他服务接管时停止。
- 解绑更新绑定代次，旧按钮草稿及旧队列不能被重新绑定的账号复用。
- 提供失败消息列表、受限重试和丢弃；待恢复连接暂停队列处理，不丢弃消息。

## 升级

1. 备份数据库、APP_KEY 和插件代码，不卸载或删除原数据。
2. 在 XBoard 上传 `FriendInvite-0.1.1.zip` 升级。
3. 确保 Web PHP 用户可写 `storage/app/friend-invite`，重启 Web / Octane 和后台任务常驻 PHP 进程。
4. 重新打开配置并开放控制台，刷新页面，运行部署自检。旧页面无配置修订号时无法保存。
5. 验证一份测试邀请、一次 TG 邀请流程和控制台关闭操作。机器人若显示待恢复，使用恢复按钮。

多个 Web 副本必须共享管理锁目录且文件系统支持跨进程 flock；只共享数据库的部署不在本版管理互斥保护范围。TG 网络故障时可清除待恢复的本地连接，但不会删除远端 Webhook，须另行核对。

## 验证与边界

回归覆盖原生鉴权、五种期限、领取事务与并发、TG 幂等、资源恢复、配置冲突、诊断兜底、Webhook 失败恢复和控制台草稿保护。测试使用合成凭据与模拟 Telegram，不修改真实 Webhook。

实际 MySQL、多副本部署及真实 Telegram 连接需要在目标环境验收。完整浏览器布局测试由 GitHub Actions 执行，本地环境未完成；不会将 DOM 测试当作布局或真实登录验证。
