# XBoard Friend Invite

为自己和朋友使用的 XBoard 站点提供一次性套餐邀请。管理员在独立后台或专属 Telegram 机器人中选好套餐、使用期限，把注册链接发给朋友；朋友在 XBoard 原有页面注册成功后，自动获得套餐。

**当前版本：0.1.0** · 插件名：好友邀请 · 插件代码：`friend_invite` · 作者：`crowveil`

这是独立插件，可与订阅桥接插件一起使用，不需要修改 XBoard 的程序文件、前端或原有表结构。它新增自己的数据表，并通过 XBoard 的模型创建账号、分配套餐。它不创建订单、不接支付，也不修改已有账号套餐。

## 安装与首次使用

1. 从 [GitHub Releases](https://github.com/crowveil/xboard-friend-invite/releases) 下载 **`FriendInvite-0.1.0.zip`**，在 XBoard 插件管理上传并启用。源码包不是插件安装包。
2. 在 XBoard 中创建需要赠送的套餐，设置权限组、额度、限速和设备数。在系统设置中**开放注册、开启强制邀请码注册、关闭全站注册试用套餐**。
3. 点击“好友邀请 → 配置”，开启“开放管理控制台”并保存。配置说明自动生成当前站点的完整控制台地址，复制到同一浏览器打开。需要同域 XBoard 管理员登录。
4. 在独立后台“设置”中勾选允许赠送的套餐，确认自动生成的注册链接模板，开启好友邀请注册并保存。
5. 到“邀请管理”选择套餐、期限，填写朋友备注，生成并复制链接。朋友无需访问插件后台，也无需使用 Telegram。

**启用本插件后，普通邮箱注册只接受本插件生成的邀请。** 用户自行生成的原生邀请码不能用于这个注册入口。首次安装时好友邀请注册默认关闭，完成第 4 步才开放。适合私人站点，不适合直接用于仍需公开注册的站点。

建议第一份邀请先用测试邮箱领取，确认 XBoard 用户管理中的套餐、到期时间和节点权限与所选内容一致，再发给朋友。

## 套餐与期限

后台和 Telegram 提供相同的五种选项：

| 选项   | 起算及到期规则                                             |
| ------ | ---------------------------------------------------------- |
| 1 天   | 注册成功后 24 小时                                         |
| 1 个月 | 注册成功后一个日历月；月底不存在对应日期时取目标月最后一天 |
| 1 年   | 注册成功后一个日历年；闰日按目标年月底处理                 |
| 3 年   | 注册成功后三个日历年                                       |
| 永久   | XBoard 的 `expired_at = null`，没有到期时间                |

邀请链接的有效期独立设置，默认 **7 天**，可选 1–90 天。例如“一年套餐、7 天内领取”，一年从领取成功时起算。

- **额度、权限组、限速、设备数**取自领取时的 XBoard 套餐；不用在插件再填一套。套餐价格和已启用的付费周期不限制这里的免费赠送期限。
- 套餐流量重置沿用 XBoard。**永久账号在当前核对的 XBoard 实现中不自动重置流量**，即使其套餐设置了按月重置。如果需要定期重置额度，选用一年或三年等有到期时间的期限。
- 套餐人数上限会在领取时检查；邀请本身不预占名额。检查与其他插件或原生购单流程之间没有全局名额锁，不宜将此作为强配额系统。
- 已创建邀请固定套餐 ID 和期限；修改套餐内容会影响尚未领取的邀请。删除套餐、取消允许赠送，都会阻止其待领取邀请。
- 每份邀请只允许一个新账号领取。现有账号续期、转套餐和批量发放不在本版范围内。
- 默认持有链接者可领取。可选“限定领取邮箱”，此时必须开启 XBoard 邮箱验证，且使用对应邮箱完成原生验证。此选项在网页创建邀请时设置。

## Telegram 机器人

机器人是可选入口。无需另外部署机器人程序，插件利用现有 XBoard 服务器接收 Telegram Webhook。使用独立机器人，避免占用 XBoard 原有机器人的 Webhook。

1. 在 Telegram 私聊 [@BotFather](https://t.me/BotFather)，发送 `/newbot`，按提示创建机器人并取得 Token。
2. 在插件后台“Telegram”填入 Token，点击“连接机器人”。当前站点需要公网可达的 HTTPS，XBoard 服务器需要能访问 `api.telegram.org`。
3. 点击“生成管理员绑定指令”，把生成的 `/bind ...` 发到**你与这个机器人**的私聊。指令 10 分钟有效，只能绑定一次。不要转发这条绑定指令。
4. 点击“刷新连接状态”确认绑定。后续可关闭网页，通过机器人操作。

| 操作        | 作用                                               |
| ----------- | -------------------------------------------------- |
| `/new`      | 选择套餐 → 选择期限 → 确认生成 → 复制邀请链接      |
| `/new 小林` | 同上，并保存朋友备注“小林”                         |
| `/list`     | 查看当前管理员最近 10 份邀请，复制或撤销待领取邀请 |
| `/help`     | 显示使用入口                                       |
| 领取通知    | 好友注册成功后，通知这份邀请的创建管理员           |

只有绑定的 Telegram 数字账号 ID 在私聊中可以管理。每次操作都重新检查对应 XBoard 账号仍是未封禁管理员。机器人不按可修改的 `@username` 判断权限，也不接受群聊管理。绑定只授权生成邀请，不代表 Telegram 账号可以直接登录 XBoard。

网页后台可以解除绑定、重新绑定或断开机器人。正常关闭控制台不会影响机器人或已发邀请。如果 Token 已连接到其他 Webhook，插件会拒绝覆盖。切换到另一只机器人前，请先断开当前连接。

通常可直接使用 Telegram Bot API 的免费消息能力；本插件不使用付费广播、AI 接口或收费服务。服务器沿用你的 XBoard 部署。

## 后台访问与调试

- 原生配置页只保留限时管理开关及动态地址。默认开放 60 分钟，独立后台可延长或立即关闭。
- 未开放时，已登录管理员只能看到配置概况；配置、邀请链接、操作接口和诊断导出都受管理开关限制。
- 页面文件本身可加载；没有管理员权限不能读取管理数据。关闭时清空当前页面的邀请链接、绑定指令等内容；已经复制到别处的内容不会被撤回。
- “关闭控制台”只关闭网页管理。“关闭好友邀请注册”会暂停新建邀请和待领取邀请注册。“禁用插件”会撤销全部未领取邀请并停用本插件功能；已开通账号保留。
- “诊断”中可开启 60 分钟 Debug，并导出 `friend-invite-diagnostics.json`。包含处理阶段、事件、错误类别、计数等脱敏信息，不包含原始异常文本、邀请链接、邮箱、Token 或绑定指令。
- 调试日志保留最近 200 条；调试关闭后仍记录必要的故障事件。插件无法控制其他 XBoard 插件、代理服务器或 Telegram 自身的日志。

更多排障和验收步骤见 [运行与验收](docs/operations.md)。

## 接入方式与兼容范围

本版依据 [cedar2025/Xboard 提交 4f48e61](https://github.com/cedar2025/Xboard/tree/4f48e61a2cbc6db5338872b6bdb45ef954ec1256) 的插件接口开发、测试：

- 通过标准插件 ServiceProvider 装饰 `RegisterService` 与 `PluginConfigService`。
- 调用原有注册服务，保留邮箱验证、人机验证、邮箱限制、注册开关、IP 注册限频和原有注册钩子。
- 使用同一数据库事务完成原生邀请码消耗、账号保存、套餐分配、插件邀请核销及通知入队。
- 原生 UserObserver 在事务提交后继续计算流量重置时间、触发节点同步；不另写节点同步服务。
- 默认链接适配核对过的 XBoard 主题：`/#/register?code={code}`。自定义主题可在后台修改模板，不需要硬编码域名。
- Telegram 通过独立插件路由接收更新，避免与原有 Telegram 插件争用解析器或机器人。

运行需要 PHP 8.2+、支持上述接口的 XBoard 插件系统、可事务处理的数据库（MySQL 原生相关表应使用 InnoDB），以及原有队列／计划任务。插件安装包不携带 Laravel 或前端构建依赖。

**不保证任意 XBoard 分支及未来版本接口不变。** 更新 XBoard 后，应重新验证配置地址、一次注册开通和机器人交互。未对你当前服务器进行远程部署，也未使用真实 Bot Token 做线上连通测试。

## 开发、测试与构建

在独立源码目录执行，不要在 XBoard 生产目录安装测试依赖：

```bash
composer install
npm ci
composer test
npm test
composer format:check
npm run format:check
python3 tools/build.py
python3 -m unittest discover -s tests -p 'test_publish.py' -v
python3 tools/build.py --check --package
```

测试环境使用 PHP 8.3、Laravel 12、SQLite，直接加载固定提交的原生插件管理器、注册服务、套餐／邀请码模型、UserObserver、TrafficResetService 和管理员中间件。其他外围服务和数据库结构使用测试替身；Telegram HTTP 响应为模拟数据。

可选真实浏览器测试：

```bash
npx playwright install chromium
npm run test:browser
```

本次后端、并发和 DOM 测试范围见 [测试说明](docs/testing.md)。`tools/build.py --check --package` 确定性生成插件 ZIP、源码 ZIP 和 `SHA256SUMS`，作为 Release 的三个独立附件；不生成套装或嵌套 ZIP。

## 从源码发布到 GitHub

完整源码 ZIP 解压后就是项目根目录，其中包含 `publish.sh`、发布工具和 GitHub Actions 工作流。仅发布时，Debian 本机需要 **Git、Python 3.9+ 和已登录 crowveil 的 GitHub CLI**；PHP、Composer、Node 和浏览器测试都在 Actions 中运行。

```bash
bash publish.sh --check
bash publish.sh
```

首次发布确认文字为 `PUBLISH v0.1.0`。脚本会在需要时创建公开仓库 `crowveil/xboard-friend-invite`，正常推送 main，等待同一提交的 Tests 通过，再启动 Release 工作流。`--check` 不创建仓库或进行任何远端写入。

完整步骤、中断恢复和后续版本操作见 [发布指南](docs/publishing.md)。这个项目没有旧版本重发开关；已正式发布的版本应递增版本号。

开发文件及发布元数据只使用 `crowveil` 公开身份。源码不包含 Git 历史、私人站点地址、机器人凭据或调试日志。MIT 许可证；上游测试样本保留其许可证。
